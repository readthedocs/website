{# Open source philosophy #}
{{ section_header("Built for the open source community") }}

Our mission

Read the Docs was founded to improve documentation in the open source community. Our vision is to be the best place to host software documentation using a docs-as-code approach.

Documenting projects is hard, hosting them shouldn't be. Read the Docs was created to make hosting documentation simple: to encourage people to write documentation by removing the barrier of entry to hosting, and to create a central platform for people to find documentation.

Community supported

Read the Docs is open source and community supported. It depends on people like you contributing to development, support, and operations.

{# Community vs Business #} {% with highlight="community" %} {% include "includes/platform-comparison.html" %} {% endwith %} {# FAQ #}
{{ section_header("Community FAQ") }}

Is it really free?

Yes. Open source documentation is always free on Read the Docs Community, supported by a single non-tracking ad on the documentation.

Can I host private documentation?

Read the Docs Community only supports public Git repositories, and all documentation is publicly accessible to the world. For private repositories and documentation that requires authentication, use Read the Docs Business.

Which Git providers are supported?

Read the Docs integrates with GitHub, GitLab, and Bitbucket and can clone and build documentation from any hosted repository. You can also manually connect to any repository provider that supports Git.

What support is included?

Email support is included for issues with our platform. Read the Docs does not offer support for questions or problems with documentation tools or content. Learn how to get support →

How do builds compare to Read the Docs Business?

Read the Docs Community has less build time and fewer build resources (memory & CPU). See Choosing a platform for all the differences.

Can I use my own domain?

Yes. By configuring a custom domain for your project, your project can serve documentation from a domain you control, for instance docs.example.com.
