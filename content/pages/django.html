{% call about.step( header=header_1, image="/images/features/review.png", image_alt="Read the Docs build status checks on a GitHub pull request", icon=icon_1) %} {% markdown %} Read the Docs builds your documentation for every new pull request. Previewing changes during review makes it easier to **catch formatting and display issues before they go live**. We create and build a new version when a pull request is opened, and rebuild it whenever a new commit is pushed. The build status shows as one of your pull request's checks, and updates to success or failure when the build completes. {% endmarkdown %} Documentation {% endcall %}
{{ about_divide() }}
{% call about.step( header=header_2, image="/images/django/files-changed-comment.png", image_alt="A pull request comment with a link to the preview and a table of files changed", icon=icon_2) %} {% markdown %} We create a comment on the pull request including a link to the preview of the documentation, and a list of the **files that changed** between the pull request and the latest version of your documentation. Every page is linked, so reviewers jump straight to the rendered result. Add patterns for pages that always change, like archives or changelogs, and they're ignored. {% endmarkdown %} Documentation {% endcall %}
{{ about_divide() }}
{% call about.step( header=header_3, image="/images/docs-as-code/visual-diff.png", image_alt="Visual diff highlighting changed text on a documentation page", icon=icon_3) %} {% markdown %} While seeing changes in source files is helpful, it can be difficult to understand how those changes will look in the rendered documentation. Visual diff shows proposed changes by **visually highlighting the differences** between the pull request and the latest version of your documentation. Pick any changed page from the menu on the preview, jump between changed sections with the arrows, and press `d` to toggle the diff on and off. {% endmarkdown %} Documentation {% endcall %}
{{ about_divide() }}
{% call about.step( header=header_4, image=None, icon=icon_4) %} {% markdown %} Direct upload lets you **build your documentation anywhere**, for example in GitHub Actions or in any other continuous integration service, and upload the resulting files to Read the Docs for hosting. A push to `main` updates the `main` version, a new tag creates a new version, and a pull request creates a pull request preview. Uploaded documentation keeps all the hosting features you already know: versions, pull request previews, search, custom domains and downloadable formats. {% endmarkdown %} Documentation
